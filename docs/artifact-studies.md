# Artifact reconstruction studies

The artifact route compares fresh native Codex agents building a Python project
from pinned specification files. It advances partial Y03/Y04/Y07/Y10 coverage
beyond the JSON-result routes. It was added for the user-requested U-Neuron
comparison: explicitly use Dovetail versus the same task without Dovetail.

## Product workflow

Author a request using [ArtifactRequest](../src/yassa/artifact_contracts.py).
Each of `public`, `reference`, and `tests` is an external directory with an
explicit relative-file-to-SHA-256 map. `public` is the entire task-specific input
allowlist for builders. The other bundles are evaluator-only. `tests` contains
the original `pyproject.toml` and `tests/` files. Sources and arms use the existing
pinned skill-pack and explicit invocation contracts. Source packs stay outside
the Yassa checkout.

```powershell
uv run --locked yassa artifact-prepare request.json --run-dir C:/runs/artifact
uv run --locked yassa resource-init C:/runs/allocation --max-attempts 2 --max-scheduled-seconds 3600
uv run --locked yassa artifact-execute C:/runs/artifact --auth-file C:/path/to/auth.json --resources C:/runs/allocation
uv run --locked yassa artifact-score C:/runs/artifact --label original
uv run --locked yassa verify C:/runs/artifact
```

Preparation tests the original reference before freezing the review and plan.
It rejects an oracle that cannot collect and run. Existing reference test failures
remain visible and are not silently removed. Execution uses the existing native
adapter's fresh Inspect Docker sandboxes, permission probes, catalog checks,
transcript capture and resource controller. Builds export `output/project/`;
Python source should use its `src/` directory. No reference source, held-out tests
or test feedback is provided to builders.

Scoring is a separate command on sealed, saved work. It starts a fresh offline
Inspect Docker sandbox per implementation, with the frozen suite, a read-only
project, no credentials or host mounts, and no candidate installation hooks.
Pytest uses the oracle's configuration and conftest, with external plugin
autoload disabled. It imports the submitted package through `PYTHONPATH`.
Every test collected on the reference stays in the scoring denominator. Missing,
failed and skipped tests do not pass. Execution or evaluator infrastructure
failures remain missing. Raw stdout, stderr, JUnit and Inspect logs accompany
per-test results. Repeating `artifact-score` with a new label reruns only tests;
it does not call models. The frozen procedure and dependencies are required.

## Scope and limits

This is a direct artifact-building comparison, not a skill-builder/consumer
study. The task and test suite are supplied, not generated by preparation agents.
Only Python projects with preinstalled dependencies and a pytest oracle are
supported. The runtime image is pinned by immutable local image ID. A dependency
image recipe is in [Dockerfile.artifact](../runtime/codex/Dockerfile.artifact);
the recorded image and dependency inventory, rather than a future rebuild of
mutable package indexes, define the environment actually used.

Artifact roles allow 30–3600 seconds per root invocation. Root deadlines include
child work, but exclude setup, export and later testing. They do not cap tokens
or spending. Managed build execution supports the existing status, cancellation
and resume commands. Reference preparation and offline testing do not yet have
durable phase recovery. No automatic model retries are selected by default.

Tests are held out from builders and protected against file modification during
evaluation. Adversarial Python in-process tampering with pytest/JUnit is outside
the demonstrated boundary. Suite compatibility does not establish the full
mathematical specification. Multiple tests on one artifact are not independent
sampled tasks; a single pair supports a descriptive comparison only. A public
repository can also have been present in model training data.

## U-Neuron allocation

The completed [U-Neuron study record](u-neuron-reconstruction.md) owns the
source pins, explicit Dovetail treatment, resource allocation, packaging
correction and external evidence locations. It used one actual reconstruction
per arm from the two original specification sheets; original implementation
and shipped tests were evaluator-only. An initial Dovetail catalog rejection
made no inference and remains preserved alongside the corrected run.

## Recorded results

The unchanged shipped suite scored 66/87 with Dovetail, 64/87 without it and
85/87 on the original reference. The two-test difference was error-message
wording, so it did not establish a mathematical correctness advantage.

See the study's [results](u-neuron-reconstruction.md#recorded-results),

[resource tradeoff](u-neuron-reconstruction.md#resource-tradeoff) and
[evidence](u-neuron-reconstruction.md#evidence-and-verification). The next
study issue is its observable-behavior oracle and explicit public API. Existing
scores remain unchanged, and no further model allocation is implied.
